# Judge quick start

**HimanshuDigitalTwin** · Happiest Health Digital Twin Challenge 2026  
**Team:** `himanshusubh1510` · **Presenter:** Himanshu Shukla · **College:** MITS Gwalior

**Start here:** This repository contains a runnable, **synthetic** glucose digital-twin research demo. It combines patient context, CGM-like observations, meals and activity into an updated patient state, produces illustrative 30/60/120-minute forecasts, checks later synthetic observations against earlier predictions, and **withholds forecasts when the signal is too stale**.

It is **not** an approved clinical model. The separately reported CGMacros research metrics were not produced by the live demonstration forecaster.

## 2. Run the app from a fresh checkout

**Prerequisite:** Python 3.11+.

From the **repository root**:

```bash
python -m pip install -r backend/requirements.txt
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Open **http://127.0.0.1:8000**. Use the **Guided judge demo** selector and click **Show chapter**. No credentials, dataset downloads, external API key, or optional Next.js setup is required.

Alternatively, after installing the dependencies, run `run_local.bat` on Windows or `bash run_local.sh` on Linux/macOS. To stop: `Ctrl+C`.

## 3. Follow the six reproducible checkpoints

| Step | Select | What should happen |
|---|---|---|
| 1 | Baseline | Synthetic profile, initial measured CGM and versioned state |
| 2 | Breakfast | Meal context and future glucose estimates |
| 3 | **Lunch** | Current **144 mg/dL** at 12:15; illustrative **155.5 / 156.0 / 145.4 mg/dL** (+30/+60/+120 minutes) |
| 4 | Verification | Earlier forecasts reconciled against later *simulated* measurements |
| 5 | **Sensor gap** | `quality=IMPUTED`, `reading.glucose=null`, `forecast_status=ABSTAINED`, `forecasts=[]`, `excursion_risk=null` |
| 6 | Recovery | Genuine synthetic sensor values return; forecast output resumes |

Chapter selection resets that **browser's** local simulated session to a deterministic checkpoint. Each browser profile gets its own temporary replay state; browser tabs in the same profile share the cookie. This is not identity authentication or durable patient storage.

**Important nuance:** Brief gaps (up to 15 minutes since the last verified sample) may still permit a provisional forecast based on earlier valid readings. The stale-sensor checkpoint shows an actual abstention. An internally carried-forward value is never labelled as a new measured CGM observation.

## 4. Verify the claims in code

From the **repository root** in a separate terminal:

```bash
python backend/scripts/verify_judge_submission.py
python -m pytest backend/tests -q
```

The first command checks the recorded six-chapter *synthetic* trace, abstention and two-browser isolation; the second runs the regression tests. For independent confirmation, inspect the [GitHub Actions verification workflow](https://github.com/himanshu051116/Himanshu-DigitalTwin/actions/workflows/verify-submission.yml).

## Submission and scientific boundaries

- **Default app:** Synthetic replay and heuristic/illustrative forecasting. Risk estimates and demo uncertainty intervals are not clinically calibrated.
- **Separate evidence:** Independent 45-person CGMacros study; 14 participants with T2D, but only 3 T2D participants in the primary 10-person holdout. It is **not** a validation of the currently running model.
- **Unfinished:** Canonical training reproduction, external validation, approval gates, real-world clinical safety, durable user isolation and production authentication.
- **Competition submission:** A genuine **minimum-20-minute** demonstration video link, confirmed registered roster, and platform acknowledgement are not in this repository. [Exact status](SUBMISSION_CHECKLIST.md).

**No medical decisions, treatment recommendations, diagnosis, or insulin dosing should be based on this prototype.**
